## 🔍 关键发现

### 1. IOVA 分配的本质

**核心结论**：IOVA 是分配出来的，不是从物理地址换算的

**证据**：
- 源码分析：`iommu_dma_alloc_iova()` 从空闲池分配
- 理论推演：IOVA 和 PA 之间无数学关系
- 预期实验：100% 的映射显示 IOVA ≠ PA

### 2. Strict vs Lazy 失效

**核心结论**：Lazy 模式通过批量处理提升 5-10x 性能

**机制**：
- Strict：每次 unmap 立即失效
- Lazy：攒批后全域失效（10ms 或队列满）

**权衡**：
- 性能：Lazy 提升 5-10x
- 安全：Lazy 有最多 10ms 延迟

### 3. QEMU IOMMU 限制

**核心发现**：QEMU 默认禁用 ACS，导致无法创建 IOMMU 组

**源码证据**：
- QEMU: `pcie_acs_reset()` 设置 ACS_CTRL = 0
- Linux: `pci_device_group()` 依赖 ACS 创建组边界

**影响**：
- VM 中无法观察 IOVA ≠ PA
- 需要使用物理主机或修改 QEMU 源码

### 4. 三家后端差异

**Intel VT-d**：
- 自持走表器，手写 `dma_pte`
- Fault 日志：解码后的详细信息

**ARM SMMUv3**：
- 使用 `io-pgtable` 公共库
- Fault 日志：原始十六进制数据

**AMD-Vi**：
- 使用 `io-pgtable` 库，直通强制 V1
- 8KB 环形队列
